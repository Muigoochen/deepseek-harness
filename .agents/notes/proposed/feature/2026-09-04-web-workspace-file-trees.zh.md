# Agent Note: Web 侧边栏按工作区的文件树与拖拽进输入框的文件引用

Status: proposed

[English](2026-09-04-web-workspace-file-trees.md) | 中文

## Problem

Web 侧边栏把会话归到工作区下，却从不展示工作区的文件。在对话里引用某个文件需要输入 `@` 并借助 [`@` 引用发现界面](../../implemented/feature/2026-08-27-web-at-mention-discovery-and-row-content.zh.md)；该发现界面是查询形态的，无法像编辑器的文件浏览器那样给出稳定结构，用户如果不知道文件名或目录布局，就只能靠猜词搜索。

在长期项目里，一个工作区下的会话会越积越多，工作区下的扁平列表随之无界增长。[工作区的折叠状态](../../implemented/feature/2026-08-11-workspace-sidebar-order-and-folding.zh.md)约束了可见范围，但两条长尾——大量文件与大量会话——挤在同一根轴上，都没有稳定、可折叠的安放位置。

产品在收尾消息里已经能渲染[行内文件提及](../../implemented/feature/2026-08-07-web-inline-file-mentions.zh.md)，而一次动态插件原型验证了缺失的交互：在每个工作区的会话列表旁放一棵文件树，把文件拖进输入框变成 `@` 风格的文件引用。原型也暴露了正式设计必须接手的一个陷阱：把树行拖进 Lexical 输入框时，若没有显式处理，编辑器会把拖拽自带的纯文本（绝对路径）原样插入，所以 drop 处理必须落在产品输入 seam 里，而不是放在一个与编辑器竞争的浮层中。

## Proposal

让每个工作区在侧边栏里拥有自己的文件树，并让文件 drop 走既有的输入框引用机器。

### 侧边栏信息架构

侧边栏浏览区里的每个工作区节点下，是两个可独立折叠的子分支：**对话** 与 **文件**。

```
工作区 A
 ├─ 对话 ▸ (n)   沿用现有会话行
 └─ 文件 ▸       A 的懒加载目录树
工作区 B
 ├─ 对话 ▸ (n)
 └─ 文件 ▸       B 的懒加载目录树
```

对话分支**原样复用**已上线的会话行组件——运行/完成指示、待处理交互点、临时空白行、相对时间与行操作——因此本特性只做分组归位，绝不引入第二套会话行实现。文件分支是新的只读目录树，根为该工作区路径。每个工作区树的状态（展开目录、已加载缓存、滚动位置、过滤开关）相互独立，绝不与其它工作区的树共享。工作区搜索、排序、Ungrouped 桶、归档与空白会话复用全部保持现有行为。

### Host 列目录能力

现有 directory-picker 只返回子目录，因为它的用途是选目录；file-reference 搜索则是查询形态。在文件系统 seam 上新增只读的目录列举：按层返回文件与目录，边界与文件引用发现一致——相同的排除目录默认值、可用 `AbortSignal` 取消、绝不读取文件内容。相对路径按 `fs.resolve` 既有规则相对会话 cwd 解析，树以所属工作区在 Workspace registry 里的路径为根。

### 输入框 drop seam

树行拖拽时携带自定义 DataTransfer 载荷，内含工作区根、相对路径与文件/文件夹种类。composer 在产品编辑器层、编辑器默认纯文本处理之前接受 drop，转换成与 `@` 菜单选中完全一致的 `ReferenceInsert` 文件/文件夹 chip，空白路径的引号处理复用共享的 `formatFileMention` 文法。文件不在接收会话 cwd 之下时降级为绝对路径文本，而不是制造一个假的 `@` 提及。

### 持久化

每个工作区的展开、过滤与滚动状态以 `WorkspaceId` 为键存入浏览器 `localStorage`，沿用现有[会话内容宽度的 `localStorage` 先例](../../implemented/feature/2026-08-18-conversation-adaptive-content-width.zh.md)。不新增 host 或账号服务端存储。

### 启用与适配

该特性以 Web 客户端功能包形式上线，注册进 web-app bundle 组合，默认启用，一条组合行即可关闭。适配到其它项目或仓库无需改代码：树根来自 Workspace registry 路径，提及相对性来自接收会话的 cwd，排除目录默认值与开关可配置，任何路径比较前先规范化分隔符。

## Alternatives considered

- **帧级抽屉浮层**（已验证过的原型）。产品版拒绝：抽屉复制侧栏 chrome、悬浮在产品表面上，且无法与真实会话行并排挂接在每个工作区下。
- **一棵随工作区切换换根的共享文件树**。产品负责人拒绝：每个工作区必须持有独立树，因为并行项目的树各自演进。
- **复用 directory-picker 列举做树**。拒绝：它只返回目录，且属于"选目录"流程。
- **把拖入路径作为纯文本插入**。拒绝：纯文本丢掉 chip 身份、引号一致性与 `@` 界面已有的规范提及形态。
- **把树状态持久化到 host 或账号服务端**。拒绝：浏览器本地状态即匹配交互需求，树只是工作区文件的呈现，不是持久产品状态。

## Acceptance criteria

- 已上线的 Web 侧边栏中，每个工作区展示独立的、可折叠的「对话/文件」两分支，搜索、会话顺序、Ungrouped 桶、归档与空白会话复用不变。
- 展开或滚动工作区 A 的树不影响工作区 B 的树；刷新后每个树还原各自已存状态。
- 把当前工作区的文件/文件夹拖进输入框，插入与 `@` 菜单选中完全一致的文件/文件夹引用 chip（含空白路径的引号）；跨工作区拖拽降级为绝对路径。
- 目录列举绝不读取文件内容、遵守排除目录默认值、可干净中止。
- 存在不经拖拽、用键盘插入同一引用的路径。
- 启用是一条有文档的组合行；关闭即从界面整体移除该特性。
- 组件测试覆盖分支渲染与按工作区状态；Host 列举测试覆盖排除、取消与边界；组装后的无密钥场景覆盖浏览、拖拽与插入；产品文案进 locale 字典；i18n 与 snapshot 门禁通过。

## Risks

- 改造工作区浏览区可能回归排序、搜索或会话行行为；对策是复用既有树派生与行组件，并让默认表现逐字节不变。
- 深层或超大目录让懒加载变贵；按层限界、可中止列举、不在 hover 上展开，把成本保持在用户驱动范围内。
- drop 处理会与编辑器默认纯文本插入竞争（原型已观察到）；drop 处理必须落在产品输入 seam，并由浏览器级验收场景覆盖。
- Windows 盘符大小写与分隔符须在路径比较前规范化；提及引号必须来自共享文法，而不是第二套实现。
