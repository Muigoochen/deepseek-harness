# DSH-孤辰小助手

本工具供小白在 Windows 10/11 64 位电脑上「一键」装好并打开 DeepSeek Harness 网页版，无需会编程、无需等网络。

## 怎么用（给小白）

界面分三个页签：「安装与启动」「插件」「会话迁移」。第一页**左右两栏**：左边是操作区（安装位置、一键完整安装（服务在跑时自动变灰，停止服务后又可用）/ 运行 / 停止、版本与更新；**本助手自己装过的目录**会默认收起「安装方式」，点标题可展开），右边整块是终端日志——所以日志永远占满右半边，不会被上面的表单挤没。两栏中间那条**竖线可以拖着调宽窄**：拖完记住，下次打开还是这个宽度；双击竖线回到默认；左栏放不下时会出现滚动条，滚轮可用。

1. 把整个文件夹拷到目标电脑（可 U 盘/网盘）。
2. 双击 run.bat（若没有 Python 且提示找不到，先装 Python 3.11+ 或用目录里的打包 exe 版本）。
3. 在窗口里选安装方式：
   - 自动选择（推荐）：有离线数据走离线、缺的自动联网补
   - 离线安装：完全不联网（需 assets/ 数据齐全）
   - 在线安装：走网络源（较慢）

   **每一步取文件都是同一套规矩**：① 随包离线数据 → ② **国内镜像**（npmmirror）→ ③ 官方源，
   全都失败才报错。Node 安装包、pnpm 包、源码包、项目依赖都走这条链；每个来源的尝试、耗时、大小和
   失败原因都会写进右边日志，下载进度**只在原地刷一行**（不会刷屏，也不能把真正的日志冲走）。
   依赖这一步如果随包缓存里缺包，会自动改走镜像/官方补包，并**补进随包缓存**（`assets/pnpm-store`），
   所以随包数据会越用越全，之后纯离线也能装完——这是真机测试抓出来的坑：老版本在这种情况直接判死。
   离线解压出来的源码**没有 `.git`**，而构建脚本要用提交号：小助手会把 `DSH_CLIENT_COMMIT_HASH`
   喂给它（取自 `assets/source-commit.txt`；打包时写下真号就显示真号，没有就用占位值并在日志里说明），
   同时补上 `npm_execpath`——这两个值缺任何一个，构建都会直接失败。

   **更新入口按"远端拓扑"出现**（点【检查更新】后探测）：只有官方远端时只显示
   **「从官方更新」**；除了官方还有你自己的远端（fork／团队镜像）时，再多一条
   **「从你的仓库更新（owner）」**；一个都没有（离线装出来的目录）就都不显示并说明原因。
   「检查更新」**必须同时对照官方**——只跟自己的 fork 比会误报"已是最新"（真机踩过：
   本地 0.1.2-alpha.3、官方已到 0.1.6-alpha.2 却说最新）。官方那一路用 `ls-remote`
   只取引用、不拉历史：直连官方全量 `git fetch` 在受限网络里十分钟都不返回。
   更新动作：能快进就直接快进；**不是快进关系就合并**（默认不改写你的提交历史），
   合并前自动打备份分支 `backup/before-update-…`，万一冲突会**整体撤销**、你的文件一个都不动。
   官方来源按"镜像（可配 `DSH_GIT_MIRROR` 或配置项 `gitMirror`）→ 官方源"的顺序取；
   取之前先对官方做一次几秒的 `ls-remote` 探活——真机实测连不上 github 时全量 `fetch` 会一直挂到
   超时（十分钟都不返回），探不到就立刻如实报错，不让用户干等。官方**没核对上**时那一行显示
   「？ 没核对上官方（原因）」：**只有真核对过、且官方不比本地新，才会出现「✓ 已是最新」**。
   **浅克隆要留意**：线上安装出来的是 `git clone --depth 1`，历史被截断；「从官方更新」需要两边
   有共同祖先，浅克隆常常没有——工具会明说"找不到共同祖先，没法安全合并"，并给出两条路
   （先 `git fetch --unshallow` 补齐历史，或配一个官方镜像）。
   - **安装位置**：打开时会**自动认出机器上已经装好的 DSH**（包括小助手自己就放在那份安装里的情况）。
     判定「这是不是一个 DSH 检出」要过两关：
     1. **结构**：同时有 `package.json` 与 `pnpm-workspace.yaml`
     2. **内容身份**（任意一条成立即可，只增不减、不互相否决）：
        - 有本助手写的安装标记 `.dsh-assistant.json`（**离线装的目录只有这一条**）
        - 根包名是 `@deepseek-ai/dsh-root`
        - 根包名是 `@deepseek-ai/dsh` 或以 `@deepseek-ai/dsh-` 开头
        - `packages/core/` 下存在 `@deepseek-ai/dsh-*` 子包（不依赖根包名；最多扫前 40 项）

     只看第 1 关会把**任意 pnpm 单仓**误认成 DSH，所以必须过第 2 关；只看「目录布局」也不够
     （`packages/core`、`packages/api` 是极常见命名），所以要读到真的官方包名。
     已装好时提示「✓ 已检测到已安装的 DSH（根包名 @deepseek-ai/dsh-root），将直接使用」。
     - **安装标记**：源码就绪时（依赖与构建**之前**）会在安装目录写下 `.dsh-assistant.json`，记录来源链接
       （`https://github.com/deepseek-ai/deepseek-harness.git`）、安装方式（offline/online）与时间。
       离线解压出来的目录**没有 `.git`**，这份标记就是它唯一的身份凭据，同时也把官方链接绑定下来
     - **再用真 git 复核一遍**（目录选定后：打开界面、点安装、`--selfcheck`）
       会跑 **git 命令**确认「这确实是 DSH 仓库根、且远端是 DSH」，并读出**版本号、提交、分支、
       工作区是否干净、领先/落后多少**。链接交给 git 自己解析，所以 `insteadOf` 重写、
       `includeIf` 条件包含、worktree 改道都不会看错——这是读文本猜做不到的。
       远端分两档，绝不冒名顶替：
       · **官方仓库**（owner 与仓库名都对上 `deepseek-ai/deepseek-harness`）→ 最强依据，显示为绿色
       · 仓库名对得上但**不在官方名下**（你自己账户下的 fork、镜像、本地克隆）→ 也算 DSH，但会明说
         「非官方远端 …（仓库名对得上，但官方是 deepseek-ai/deepseek-harness）」，显示为橙色
       代价约 0.2 秒，所以只跑在**你选定的那一个目录**上，绝不参与扫盘（扫盘只看文件，不跑 git）。
       离线解压的目录没有 `.git`，会退回文件判定并如实说明依据
     - **内容是门槛，git 远端是加固**（故意的深度防御）：**内容身份**成立即可确认
       （离线解压的目录没有 `.git`，只能靠它，记为「文件判定」）；**git 远端成立但内容不像 DSH**
       则**不确认**——两种最容易出事的误判因此被挡住：
       · 碰巧也叫 `deepseek-harness` 的别的仓库（内容不像 DSH）
       · 自己的单仓里只是加了官方远端当 upstream（内容不像 DSH）
     - **两条都不成立时：先提醒，再让你试跑，用「能不能真的跑起来」定案**
       （`pnpm dsh web` 只有在目录里确实是 DSH 时才打得开网页，这比读包名更硬）：
       · 输入框下方提示「？这里有内容，但认不出是 DSH —— 可以先点【运行】试跑确认」（橙色）
       · 点【运行】会先弹一个提醒说明理由，你确认后才真的试跑
       · **跑起来了**（日志里出现 `dsh web: <地址>` 那一行）→ 写进 `.dsh-assistant.json` 的
         `verifiedByRun` 字段，日志里提示「运行验证通过」；从此这个目录按已安装处理，
         输入框提示变绿，也不会再问你
       · **没跑起来** → 日志里写明「运行验证 ✗ 没能跑起来」，**不写任何标记**，下次仍会提醒你
       · 安装（会真的跑 pnpm 安装/构建）**不享受这条放行**：仍要求两条证据至少一条成立，
         认不出就中止并提示你改用空目录
     - **别人 fork 了怎么办**（都实测覆盖，见 `tests/test_catalog.py` 的 `VerifyInstallDirTest`）：
       | 用户的布局 | 判定结果 |
       |---|---|
       | 用本助手装的（origin = 官方） | ✓ 官方仓库 |
       | 自己 fork，origin 指向自己的 fork，没有官方远端 | ✓ 认（橙色）并写明「非官方远端…官方是 deepseek-ai/deepseek-harness」 |
       | 自己 fork，origin = fork 且 upstream = 官方（本机就是这种） | ✓ 官方仓库 |
       | 连根包名都改了（fork 改名），但 `packages/core/*` 仍是官方包名 | ✓ 认（靠子包名 + 远端） |
       | 包名全改过、远端和标记都不像 | ？不确认：提醒后可以【运行】试跑定案（成功就记下来） |
     - 优先级：**界面当前输入** → 配置里的真实安装 → 自动检测到的已安装 → 配置里的空位 → 方案 A 默认。
       自动检测的顺序：小助手自身所在检出 → 用户目录下常见命名 → 各盘根下的常见命名及其再一层。
       只在**固定盘**上扫（跳过可移动/网络/CD 盘以免卡住），逐盘扫描有 3 秒预算，结果缓存一次。
     - **安全闸**：安装前若目标目录里有 `package.json` 却不是 DSH 检出（= 你自己的项目），
       会**直接中止并提示换目录**，绝不会在你的项目里跑 pnpm 安装/构建
       （若它其实是你自己改过的 DSH，提示会告诉你可以先【运行】试跑把它认下来）
     - **安全闸（第二条）**：目标目录**非空**、又没有 DSH 身份（没有安装标记、也没有官方包名）时
       同样中止——**离线解压**也会往目录里铺源码并覆盖同名文件（实测：用户自己的 `README.md`
       会被改成官方 README），不是只有在线 `git clone` 才要求空目录。这条提示会列出现有内容，
       且**不会**引导你把外部目录拿去「试跑」
     - **离线解压对符号链接容错**：`source.tar.gz` 里有 11 个仓库内镜像链接
       （`CLAUDE.md → AGENTS.md`、`.claude/skills`、`snapshots/*`），非管理员且未开开发者模式的
       Windows 上 `tar` 建不了它们并返回非零码。这时只要**源码内容完整**就继续安装，并把这 11 个
       镜像**复制**一份补上（复制不需要任何权限），不会因这点报错把默认的离线安装整条堵死
     - 输入框里**敲键盘不影响任何东西**：位置只在**回车或点别处**时才切换（免得误碰一下，
       后面的「运行/自检/插件」就全指向别的目录、启动不起来）；还没确认时输入框下方会写明
       「改动尚未生效」
     - 从「已经装好的 DSH」改到「认不出的目录」时会**先问一句**（默认退回原位置）——
       误碰点「否」就还原，真想换地方重装点「是」；确认后才记进配置
     - 清空输入框不会把安装位改成方案 A，而是交回自动识别
     - 【浏览…】选中的目录**原样采用**（含 `deepseek_harness` 这类下划线命名），只有选到盘根才补默认名；
       选到父目录会自动下钻到里面那份安装
     - 【回到上次位置】= 配置里记住的位置 → 机器上自动识别到的已安装目录 → 才是方案 A 默认值。
       **不再无脑跳 C 盘**（以前装在别的盘上的那份位置会被丢掉，那既不是「默认」也不是「上次」）
     - 输入框下方实时提示（红=不能装，橙=可装但有风险，绿=已装好/可用）
     - 默认 `%USERPROFILE%\deepseek-harness`；系统盘空间不足 8 GB 时自动回退到其它盘
       （回退目标本身要求有 ≥20 GB 可用空间）
     - DeepSeek Harness 本体从**官方仓库**独立克隆到该位置，与小助手所在目录无关
4. 点【一键完整安装】：自动装 Node → pnpm → 源码 → 依赖 → 构建 → **启动网页版**（日志实时可见），
   启动完点【打开登录页】即可进入。
5. 装好后日常用一个按钮：
   - 【运行】：在窗口内运行 dsh web 并实时看日志（与左侧「⏹ 停止服务」互斥；运行中可「打开与复制」）
6. 「打开与复制」区（服务运行后可用）：
   - 下拉选浏览器：默认浏览器 / Edge / Chrome / QQ 浏览器 / 火狐，或「自定义…」手动选 exe
   - 【打开登录页】：用所选浏览器打开带 token 的登录地址；**没运行时会自动启动服务再打开**
   - 【复制登录地址】：一键复制带 token 的完整地址，粘到任意浏览器即可完成登录
   - 【复制项目路径】：一键复制源码目录路径
7. 「版本与更新」区（安装位置下方；结论全部来自**真实 git 命令**，不是读文本猜的）：
   - 一行给出：**版本 v0.1.2-alpha.3 · 提交 ea0874cdfc（日期）· 分支 plugins · 工作区 N 处本地改动 ·
     相对 origin/plugins 领先/落后**，另起一行给出**凭什么确认**
     （例：`依据：官方仓库 git@github.com:deepseek-ai/deepseek-harness.git`）
   - 若分支跟踪的远端不是官方（例：你把自己的 fork 设成了 origin），会再多一行
     `更新来源：origin/plugins（…，非官方 —— 官方更新需自行合并）`，免得你以为在跟官方同步
   - 【刷新信息】重读一次；安装位置一改会**自动重读**（延迟 0.4 秒，不打扰输入）
   - 【检查更新】：`git fetch` 后**由 git 比较**，直接告诉你「落后 N 个提交（最新是 xxx）」或「✓ 已是最新」，
     并标出是跟**哪个远端**比的（非官方会写明）。比的是**分支跟踪的那个远端**（`@{u}`），
     不是硬编码 origin：小白装的 origin 通常就是官方，开发机上分支跟踪自己的 fork 就该跟它比。
     这是「版本与更新」区里唯一会联网的操作，没网/远端不可达会明确报出原因，**不会假装成功**
     （装 Node/pnpm、在线安装、下载插件也会联网，见「支持范围与注意」）
   - 【更新到最新】：确认后 **git fetch → 只做快进**（`merge --ff-only`，绝不产生合并提交）→
     重装依赖 → 重新构建 → 若服务原本在运行会自动重新启动。三条安全线：
     · **工作区有本地改动就拒绝**（先把改动提交或撤销），绝不覆盖你的东西；
     · 「能不能快进」**交给 git 判断**，不自己数提交数——线上装的是 `git clone --depth 1` 浅克隆，
       数提交会把边界提交各算一次，自己算会误判成「有本地独有提交」而瞎拒绝；
     · 服务在跑会**先停**再更新（Windows 上被占用的 node_modules 文件没法替换）
   - 离线装出来的目录没有 `.git`，这里会退回文件判定并写明依据；没装 git 也会如实说明
8. 「插件」页：**一张统一列表**，一行一个插件，**状态词全页一套**——`已启用／已停用／已下载／未下载`
   （外加内置的 `内置`），后面紧跟一列**来源**说明它是哪种插件，所以不用先学会两套概念再看：
   - **来源**：`本地补丁·你写的`＝你手写的补丁行；`本地补丁·助手管理`＝助手安装并记账的；
     `在线包`＝bundle（走 `dsh plugin add`）；`内置插件·你加的`＝`@deepseek-ai/*` 的官方插件；
     `内置清单`＝还没下载的内置清单项
   - **版本号**：从插件自己的 `package.json` 读，本地插件的版本列不再是「—」
   - **校验**：三种插件都有——本地/官方插件查共享包目录与来源目录，在线包查它的安装前置要求；
     都回答同一个问题「这个包能不能装、能不能跑」
   - **本地插件**：只显示你在补丁里声明过的行；【重新扫描】列出已启用/已停用/已下载的行；
     安装/禁用/启用/卸载先记为**草稿**，点【全部保存并重启网页版】落盘并重启验证（写盘前跑结构门校验，
     写坏或未生效自动回滚 `.bak` 再重启）；【接管】只对**真的能接管**的 `@dsh-user/*` 行显示
     ——单条目、没有 `config`、没有注释的行才接得了（带 config 的行助手不碰你的配置，按钮就不给）；
     本地插件的改动是**草稿**：点完行内按钮后保存按钮会变成「全部保存并重启网页版（N 项待保存）」，
     状态栏也会提示，别以为点了没反应。**反悔有两条路**：
     · **【撤销待办】**——只清掉还没保存的草稿，**一个字节都不写盘**（点错了、改主意了用这个）
     · **【回滚到上次保存…】**——真的动文件：把补丁**和台账一起**退回到上一次写盘之前
       （备份是每次写盘（保存/禁用/启用/接管/安装/卸载）之前自动留的 `.bak`，备份保留可重复回滚；
       正在跑的网页版要重启才看得到结果）
   - **在线插件（bundle）**：安装/卸载/校验/查看更新**即时执行**——真实写入 `$DSH_HOME/profiles/web`
     （备份 package.json、失败回滚；内置 `@deepseek-ai/dsh-base` 等不列、不可删；需重启网页版生效）；
     行内按状态显示：未下载→【下载】、已下载未装→【安装】+【校验】、
     已启用→【禁用】+【卸载】+【校验】+【查看更新】、已停用→【启用】+【卸载】
   - **【禁用】/【启用】是排查插件冲突用的开关**（场景见下面「插件起冲突、dsh 打不开怎么办」）：
     外部行也能禁停、**不必先接管**；禁用只写官方支持的 `disabled: true`，**不改你写的任何一行**
   - **【打包发行】＝ 把本地插件一键做成可发布的 npm 包（bundle）**（详见下面「要发行怎么办」）
   - 【查看更新】→ 查 registry 最新版；有更新变【可更新】→ 点升级；无更新/查不到显示【已最新】
   - 顶部「链接下载」行输入 URL / npm 包名 / git 源下载；「从文件夹导入…」把带 package.json 的目录拷进
     小助手自己的插件来源目录（`$DSH_HOME/plugins-src/`，不写进 dsh 检出）
   - 收录名 / npm 包名 / URL 走 registry 直装（用预构建产物，不克隆不构建）；本地目录缺 `lib/` 才用 pnpm 构建
   - **自研插件走各自独立仓库**：内置清单里每个插件一个公开仓库（`lsp-echo`、`repeat-stream-guard`、
     `compaction-director`、`conversation-summary`、`toast`、`workspace-files`）。未下载时行内显示
     【下载】→ 从该插件自己的仓库 `git clone` 到 `$DSH_HOME/plugins-src/<slug>/` → 再【安装】。
     小助手不依赖自身所在仓库；只改清单 `PLUGIN_REPOS` 即可增删（见 `plugin_store.py`）
   - 【复制清单】整表复制；v0.1 限制：不改插件 config；详见 docs/插件管理-设计.md

   **插件起冲突、dsh 打不开怎么办（从外面禁用/启用）**：某个插件坏了或互相冲突时，dsh 是**硬失败**
   （直接退出，没有"安全模式"），而小助手不依赖 dsh 运行，所以这种状态下仍能救急：
   - 此时插件页照样列得出插件：结构门跑不了就**直接读补丁**列行，页面顶部会亮一行橙字说明
     「当前是免校验模式」（列表来自文件，不是 dsh 的输出）
   - 对可疑的那一行点【禁用】（外部行、你自己写的行也有这一项）：
     · **你手写的行**→ 写成官方的 `- id: xxx` + `disabled: true` 覆盖行，放在小助手自己的
       「应急开关段」里，**你原来那几行一个字都不动**（config、注释、顺序全保留）
     · **bundle** → 把包名从 `dsh.profile.bundles` 里摘掉；包文件与依赖都留着，启用是瞬时的，不用重装
   - 结构门过不去（正是因为 dsh 起不来）时会问一句「要以应急方式直接写吗」——**免校验直接写盘**，
     写前备份补丁 `.bak` 可随时回滚；写完重启 dsh 看是否恢复
   - 【启用】把改动还原：覆盖行删掉、bundle 插回原位置。**禁用一律写 `disabled: true` 而不是删行**，
     因为被删掉的行可能被 `--patch` 覆盖层重新挂回来
   - 两个前提要知道：① 若禁掉的是**服务提供者**，依赖它的插件会一直 pending、dsh 仍旧起不来
     （那就换一行再试）；② 带客户端界面的插件要刷新页面/重启才看得到变化

   **要发行怎么办（一键打包，不用再让对话去跑脚本）**：DSH 官方认可的发行形态就是 **npm 包（bundle）**——
   包里自带一个 `cordis.patch.yml` 配置层，用户一条命令 `dsh plugin add <你的包>` 就装上了，
   升级/卸载/回滚都交给包管理器。点本地插件行的【打包发行】即可
   （第一次让你填一次 npm 包名前缀，之后记住，所以之后就是真·一键）：
   - 自动改造 manifest：加 `dsh.bundle.patch`、把 patch 加进 `files`、去掉 `private: true`、
     补 `publishConfig.access`、把 `@deepseek-ai/*` 依赖从 `dependencies` 移到 `peerDependencies`
     （官方包由用户的 dsh 安装提供，钉 registry 版本只会打架）；原有 `dsh.client`（浏览器半）原样保留
   - 自动生成包内 `cordis.patch.yml`：**沿用你 `install/patch.example.yml` 里那几行**，只把包名换掉——
     发行版的挂载方式和你现在本机跑的完全一致，只是从"profile 里的行"变成"包内的层"
   - `pnpm pack` 出 tgz，并逐条自检：包里有没有配置层、manifest 有没有声明 `dsh.bundle.patch`、
     入口与浏览器半在不在包里
   - 产物落在 `$DSH_HOME/plugin-dist/<插件>-<版本>/`；**不改源目录、不装进你的 profile、不发布**
   - 之后两条命令留给你手动执行（发布不可撤销、且需要 npm 登录，所以不自动化）：
     本机试装 `dsh plugin --profile web add "<tgz>"`；发布 `cd <暂存目录> && pnpm publish`
   - 不想发 registry 也行：把 tgz 直接发给别人，或 `dsh plugin add github:你/仓库#<sha>`（后者要处理构建授权）
   - 没写 `license` 的包**不会替你猜一个**——授权是作者的决定，日志里只提示你补上

9. 「会话迁移」页签：把**已开始的会话**迁到别的 preset（例：cordis-director 启用引擎热切）
   - 列表 = 扫描结果（会话 ID / header preset / 缓存 preset / 大小 / 工作区）
   - 选中一行 → 选目标 preset →【写入（迁移）所选】：**先备份被改的两个文件本身**（绝不整目录），
     改 `session.jsonl.zstd` 第 0 帧与投影缓存的单个字段后自校验；写入前请先停止 dsh web
   - 【校验所选】复查两处取值；【从备份恢复…】一键还原；【打开备份文件夹】直达备份目录
   - 内核 `migrate.mjs` 随包自带，不依赖 DSH 运行时；改完重启 dsh web 生效

## 目录结构

   小助手文件夹/
   ├─ run.bat             双击启动图形界面
   ├─ installer.py        主程序（含「插件」区；工作线程更新界面一律经 `_post` 队列，不用 tkinter 的 after）
   ├─ gitinfo.py          git 命令层（真跑 git：识别仓库根与远端、版本/提交/分支、检查更新、快进更新；纯标准库）
   ├─ childproc.py        子进程登记（关窗时把安装/构建/克隆/拉取/插件装卸连子孙一起结束，不留孤儿）
   ├─ migrate.mjs         会话迁移内核（扫描/写入/校验/恢复；Node 22.19+ 或 24+、零依赖，随包分发）
   ├─ plugin_store.py     插件管理原语（纯标准库：台账/自有段/结构门/接管/引用扫描）
   ├─ pack_plugins.py     离线插件包自检打包（python pack_plugins.py --plugins … --out assets/plugins.tar.gz）
   ├─ tests/              单元测试（python -m unittest discover -s tests -p "test_*.py"；
   │                      所有临时目录由 `_tempguard.py` 收进一个进程级目录、跑完整体删除；
   │                      会话迁移内核另跑 node --test tests/test_migrate.mjs）
   └─ assets/             离线数据（可整体随包分发）
      ├─ node-v24.20.0-x64.msi   Node.js 安装包
      ├─ pnpm.tgz                 依赖管理器 pnpm
      ├─ source.tar.gz            官方源码快照
      └─ pnpm-store/files/        依赖离线缓存（大头，约 1GB）

把 assets/ 四样放齐 = 完全离线、零网络可装完。

## 支持范围与注意

- 仅 Windows 10/11 64 位；接收机 Node 版本需 22.19+ 或 24+（自带 msi 自动装好）。
- 在线安装（克隆官方源码）、「下载插件」、【检查更新】与【更新到最新】都需要 **Git for Windows**（https://git-scm.com/download/win）；
  没装时界面会明确提示。完全离线安装（assets/ 齐全）不需要 git。
- 首次「构建」在目标机本地进行，约 5-15 分钟、不联网；之后启动秒开。
- 安装 Node 若弹系统权限窗口，请点【是】。
- 杀软可能提示「未知发布者」，选择信任/仍要运行即可（本项目未签名）。
- 网页版地址每次带一次性 token；以窗口/终端里打印的「dsh web: http://127.0.0.1:3080/?token=…」那行为准。换浏览器访问，先用【打开登录页】或【复制登录地址】登录一次（Cookie 按浏览器独立，默认有效期 30 天）。
- **关窗会连子孙进程一起结束**：关闭窗口时，`dsh web` 连同它拉起来的 node**以及正在跑的安装/构建、
  插件安装/卸载/打包**一并结束（Windows 上父进程退出不会自动带走子进程，所以是把整棵进程树
  `taskkill /T` 掉，端口立刻就释放）。
  【停止服务】按钮结束的是 `dsh web` 那棵树，**安装/构建期间它是灰的**（那时 `node_modules` 正被写，
  没有「停一半」这种状态）；要中断安装请直接**关窗口**，关之前会问你一句。
- **关窗时如果正在安装/更新**：会先问一句；确认关闭才中断，并记下**被打断的那个目录**。
  下次对同一个目录点【一键完整安装】会自动**重新装依赖、重新构建**——否则 `node_modules` 一存在就被当成装好了。
  只是读一下 git 信息（打开界面、改路径后的自动刷新）**不算**「正在进行」，不会弹窗、也不会记标记。
- **强杀/崩溃也不留孤儿**：所有子进程都绑在 Windows 的 Job Object 上（`KILL_ON_JOB_CLOSE`）——
  用任务管理器强杀、程序崩溃、甚至断电时，句柄随本进程关闭，系统会自动结束它们（含孙子进程）。
  `--selfcheck` 会报「关窗保险」这一项；极少数环境里绑定会失败（例如已在不允许嵌套的 Job 里），
  此时退回「只在正常关窗时结束子进程」，强杀仍可能留下 `node.exe`。
- **唯一的例外是 Node 的 MSI 安装**：它真正的安装动作由 Windows Installer 服务完成（不是我们的
  子进程），所以故意既不进 Job、也不被关窗打断——打断它只会触发回滚或留下半装的 Node。
  界面若在这步关掉，下次【一键完整安装】会检测到已装好的 Node 继续往下走。
- **干净机器上「安装 pnpm」这一步**：npm / corepack 在 Windows 上是 `.cmd` 批处理，助手先用
  `shutil.which` 解析出全路径再调用——以前裸写名字会报「系统找不到指定的文件」，而这步**只在
  机器上还没有 pnpm 时**才走到，所以在已经装过 pnpm 的机器上一直看不出来。
- **配置文件是原子写的**（临时文件 + 原子替换）：写盘中途被打断也不会把已有配置毁成空文件。
- `run.bat` 找解释器顺序：本机已知路径 → 官方 `py` 启动器 → `python`——先走 `py` 是为了避开
  PATH 上那个 Microsoft Store 占位程序（它跑起来只会打开应用商店）。

## 排错

- Chrome/Edge 打开提示「dsh web authentication required」：该浏览器还没登录过。点【打开登录页】，或【复制登录地址】后粘给它打开一次即可。
- 控制台乱码：是终端代码页问题，不影响安装。
- 报「离线模式缺少…」：assets/ 不完整，改用自动/在线，或补全离线文件。
- 「版本与更新」显示「✗ 未确认是 DSH 安装」：该目录不是 DSH 的 git 仓库根（例如只是它里面的一层子目录），
  点【刷新信息】看后面的具体原因；【检查更新】失败会写明是没网、远端不可达还是没装 git。
- 显示「？无法确认是不是 DSH」：输入框下方会提示可以点【运行】试跑一次。
  跑起来了就自动记下（`.dsh-assistant.json` 的 `verifiedByRun`），以后直接认；跑不起来会写明原因，
  说明那个目录确实不是能用的 DSH 安装。
- 【更新到最新】提示「工作区有 N 处本地改动」：这是**故意的保护**——先 `git commit` 或 `git checkout -- .`
  处理掉这些改动再更新，否则可能覆盖你自己的东西。提示「不是快进关系」说明你本地有自己的提交，
  需要自己决定怎么合并；工具不会替你强推或丢提交。
- 需要模型密钥：在网页版界面里配置，或写进项目根目录 .env 的 DEEPSEEK_API_KEY=...。
