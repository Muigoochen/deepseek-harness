## 1. 问题

`Engine.prepare_source()` 的安全闸**只覆盖在线分支**。离线分支（解压随包源码 `assets/source.tar.gz`）
**不检查目标目录是否为空**，直接把源码解开到用户选的目录里；解压后该目录就成了"合法的 DSH 检出"，
后续 `install_deps()` / `build()` 会**在用户目录里**跑 `pnpm install --frozen-lockfile` 与 `pnpm run build`。

## 3. 触发条件（为什么这不是理论问题）

1. 机器上 `assets/` 齐全 → `use_offline()` 在 `auto` 模式下**就选离线**（`installer.py:777-780`），
   也就是**默认走离线分支**；
2. 用户把"安装位置"填成/选成一个**非空、但没有 `package.json`** 的目录 —— 桌面、文档、资料盘里某个文件夹、
   已经是别的工具目录的文件夹，都符合；
3. 于是 `tar -xzf` 把 DSH 源码**解压进那个目录**（会覆盖同名文件），随后在其中跑 pnpm 安装与构建。

`check_install_dir()`（`:621-650`）对此只会给**警告**（它只把 `C:\Windows`、`Program Files` 当错误），
所以界面上不会阻止用户继续。

## 4. 建议修法（最小改动）

在**解压之前**加与在线分支同等的检查，并把"三步前置条件"统一：

```python
if offline and SOURCE_ARCHIVE.exists():
    if _nonempty_dir(project):
        # 已确认是 DSH 检出的情况在 :862-865 已经 return 了，走到这里说明不是
        raise InstallError(
            f"{project}\n"
            "这个目录不是空的，也没有 DSH 安装的身份凭据，离线解压会覆盖里面的文件。\n"
            "请把「安装位置」换成一个空目录，或指向已装好的 DeepSeek Harness 目录。\n"
            "如果它其实是你自己改过的 DSH（例如包名全改了），可以先点【运行】试跑一次：\n"
            "能打开网页就说明确实是，我会把它记下来，之后就能直接复用。")
    project.mkdir(parents=True, exist_ok=True)
    proc = run(["tar", "-xzf", str(SOURCE_ARCHIVE), "-C", str(project)])
```

要点：
- 文案照 `installer.py:868-875` 的既有风格写全"**为什么中止 + 三个可选做法**"（那是给小白看的范本）；
- 同一个 `preflight()` 思路最好也覆盖 `install_deps()` / `build()` 的入口（防止别的路径绕过），
  但**最小修复只需上面这一处**；
- **不要**顺手改动 `check_install_dir()` 的警告/错误分级、也不要改在线分支行为（本工具的其它路径依赖它们）。
