## 0. 目标、范围与术语

目标：在 `tools/dsh-offline-installer`（DeepSeek Harness 安装助手）里加一个「插件」区，
把插件的 **下载 → 安装 → 启用/停用/卸载** 做成可视化操作，小白与开发者共用同一入口。
范围边界：**只管理"按产品安装注册规范进入产品的用户/三方插件"**；产品内置基座行
（`@deepseek-ai/*`）不在管理范围。实现不引入 YAML 解析依赖（保持 Python 标准库）；
`installer.py` 之外新增独立模块 `plugin_store.py` 以便测试；不动仓库原生代码
（apps/ packages/ vendor/）。

| 术语 | 含义 | 产品可感知 |
|---|---|---|
| 下载 | 插件文件进入来源位置（项目 `plugins/`、离线资产 `assets/plugins/`、`assets/plugins.tar.gz`、下载目录） | 无 |
| 预设 | 产品维护的推荐清单（catalog JSON：name/description/version/来源），助手据此一键下载/安装 | 无（v1 才做） |
| 安装 | ① 包同步到共享解析锚 `~/.dsh/profiles/node_modules/@dsh-user/<目录名>`；② 在 `profiles/web/cordis.patch.yml` 的自有段（§5）内新增该插件行（进台账） | 有（组合里出现该插件） |
| 启用 | 行内无 `disabled` 或为 false → 下次装载执行 apply | 有（装载运行） |
| 停用 | 行内 `disabled: true`；行仍在 = 已安装未跑 | 有（反注册） |
| 卸载 | 从自有段移除该行（出台账）→ 引用扫描 → 停 web → 删共享锚目录（可选保留文件）→ 回到"已下载" | 有 |
| 外部行 | 补丁中 `name == '@dsh-user/<名>'` 但不在台账（install.ps1 / 手动 / 旧版写入） | v0.1 只读 |
| 第一方行 | 补丁中 `@deepseek-ai/*` 行（如 time-context） | 可停用、不可卸载，助手不接管 |

### 1.1 组合层序与装载行为 `[已核实·代码]`

- 层序：bundle 基座 < 用户补丁 `profiles/web/cordis.patch.yml` < home 层补丁 <

  与 profile.spec.ts。
- 冷启动解析失败 = **硬失败**：`loadOptionalPatches` 抛错、进程退出
  （app-boot/src/index.ts:280、user-patches.spec.ts 的 throw 用例）。
- 运行期热应用失败 = **软失败**：HMR 事务回滚、进程存活；热应用依赖 Cordis HMR +

  刷新瞬间包目录已可解析；**已装载插件同路径宿主代码升级不热重载**
  （config-only HMR + ESM loadCache）→ 需重启。改 client.js 走 client-hmr。
- 客户端插件行的可见性依赖页面刷新/重启（R15）。

### 1.2 `dsh web --dump-config` 的能力与边界 `[已核实·代码][已核实·实测]`

- 存在且免完整启动：`dsh --profile web --dump-config`（`dsh web --dump-config` 同义）。
  与装载共用同一 entryListSchema 方言（vendor/include/src/index.ts:20,46；
  app-boot profile.ts 的 applyEntryPatches 同一调用），故 dump 结果与装载解析一致。

- 能力边界：renderConfigDump **不 eval `!!js`、不 import 模块、applyEntryPatches 未命中

- ⚠️ **dump 并非零副作用 `[已核实·实测]`**：`runDumpConfig` 会调用 `prepareProfile`，
  对 `$DSH_HOME/profiles/web/cordis.yml` 执行写操作（2026-09-05 在沙箱拦截写 home 时以
  EPERM 暴露堆栈确认）。结论：结构门不能假定只读，且与运行中实例共享同一 home 时有
  写竞争风险 → 定稿采用"克隆 home 结构门"（§6），把一切写副作用隔离到克隆内。
  （记为新风险 R20，§10。）

## 2. 状态模型

管理意图（台账/行 disabled）× 有效组合（dump 输出该条目存在且未 disabled）合成 GUI 三态：

| GUI 状态 | 判定（合成） | 可用操作 |
|---|---|---|
| 已下载（未安装） | 来源目录存在；补丁内无该插件行 | 安装 |
| 已安装·已停用 | 台账/行在且 `disabled: true`（dump 无该有效条目） | 启用 / 卸载 |
| 已安装·已启用 | 台账/行在且无 disabled；dump 有效组合含该条目 | 停用 / 卸载 |
| 外部行（只读） | 补丁内 `name == '@dsh-user/<名>'`，不在台账 | 提示来源；「接管」v0.2 |
| 第一方行（只读） | `@deepseek-ai/*` 行 | 停用/启用可用；卸载不可用 |
| （未下载） | 不在任何来源，不在补丁 | 下载/导入（v1） |

判定规则：行 = 管理意图；**"已启用"以有效组合（dump）为准，不与行内 disabled 简单等同**。
GUI 状态刷新 = 本地台账/行判定 + 一次结构门 dump 结果合成；dump 失败时 UI 显示
"未知（校验失败）"并把失败原因落到日志，不猜测状态。

## 3. 受管单元与保护锁

- 主判据：受管 = 顶层「无自身 id 的 `- insert:` 元素」且其子条目
  `name == '@dsh-user/<目录名>'`；可程序化字段仅子条目 `id` / `name` / `disabled`。
- 源判据（discover_sources）：`package.json` 的 name 恰为 `@dsh-user/<目录名>` +
  `lib/index.js` 存在；声明 `dsh.client` 时必须含 `lib/client.js`，缺则**拒绝安装**
  （client-modules 读字节失败会 FAILED 并拖垮冷启动）。名称伪装防护：name 精确校验 +
  目录名校验；多源同包名报错可读化（R17/R18）。

识别边界表（以下形态一律受保护/只读或拒改；`[拒改]` 表示受限方言解析器遇之
fail-loud、字节原样保留）：

| 形态 | 处置 |
|---|---|
| 受管元素（无自身 id 的 `- insert:` + `@dsh-user/<名>` 子条目） | 可编辑（id/name/disabled） |
| 带自身 `id` 的 insert（追加进既有 group 行） | 只读展示 |
| 无 insert 的 id-target override（`{id, disabled/config}`，可指向 @dsh-user 行并影响状态） | `[拒改]` 只读展示 |
| group 嵌套内藏 @dsh-user 子行 | `[拒改]` 提示人工处理 |
| flow / 别名 / 引号 / `!!js` / 多行字符串内含 `name:` | `[拒改]` 字节原样保留 |
| 受管元素的前导注释与行内尾注 | 整元素替换时须保住（冲突策略 D7） |
| `@deepseek-ai/*` 第一方行 | 只读展示；停用/启用可用；不可卸载 |
| 外部 `@dsh-user` 行（无台账） | v0.1 只读展示；「接管」（重写进台账自有段）v0.2 |
| 文件里其它一切内容（含未来未知形态） | 只读，助手永不写 |

受限方言解析器与卸载引用扫描**共用同一实现**（plugin_store 内部私有模块）。

## 4. 台账（ledger）与写盘模型

文件：`$DSH_HOME/profiles/web/.dsh-plugin-ledger.json`。台账只记录**助手自己创建**的
插件行（管理意图），不含任何受保护行。

```json
{
  "version": 1,
  "plugins": [
    { "id": "conversation-summary", "name": "@dsh-user/conversation-summary", "disabled": false }
  ]
}
```

- **自有段**：补丁文件末尾、由注释标记包住的一段连续区域，只含助手受管行。

  ```yaml
  # --- dsh-offline-installer managed: start ---
  - insert:
      - id: conversation-summary
        name: '@dsh-user/conversation-summary'
  # --- dsh-offline-installer managed: end ---
  ```

  写盘 = 按台账把**自有段整体重写**（模板渲染 id/name/disabled，不写 config）；
  段外内容一律不动。追加 = 台账加行后重写整段；删除 = 台账删行后重写整段；
  启停 = 改台账 disabled 后重写整段。写前 `.bak` 快照 → tmp 文件 → 结构门
  （§6，通过才）→ 原子 rename。
- **段连续性约束**：若发现自有段之后/之内出现非助手内容（外部追加、用户手插行），
  视为分叉：`[拒改]` + 只读 + 提示人工（v0.1 不自动重排，绝不吞并他人内容）。
  段标记注释缺失 = 视为"无自有段"（现网外部行不受影响）。
- **冲突策略（D7，覆盖 v0.4 的字面"按 ledger 字节范围"表述）**：台账元素在盘上若出现
  台账未知字段（如用户手加 config/字段），**中止本次写并提示人工**，绝不覆盖。
  因助手写的行永远不落 config，此类冲突只在用户手改自有段时出现，概率低、处置保守。
- **config 约束（D3）**：v0.1 安装/启停一律不写 config，用插件代码默认值
  （conversation-summary 的 resolveConfig 默认即推荐值且越界 fail-loud）。
  插件自带 `install/patch.example.yml` 只作为未来受限标量编辑的模板来源（v1.1），
  v0.1 不落盘。已有 config 的外部行原样只读保留。
- **首次归账决策（D4）**：现网 5 行（§1.3）**不归入台账**。理由：台账承载助手对行的
  所有权；现状行来源混杂（install.ps1/手动/旧版），归账 = 把用户自有内容纳入可改面，
  违背保护锁。"接管"归 v0.2。

## 5. 校验与恢复闭环（双门）

### 5.1 结构门（写前）

流程：模板渲染新补丁 → 写 `.bak` + tmp → **克隆 home 校验**：

1. 把 `$DSH_HOME` 下校验所需目录复制到临时 home（默认整拷 `profiles/web` 与解析锚
   `profiles/node_modules/@dsh-user`；能否剥离 node_modules 待 U10 冒烟定——
   dump 不 import 模块，期望可剥离）；
2. 用新补丁字节写克隆内 `profiles/web/cordis.patch.yml`；
3. 子进程以 `env DSH_HOME=<克隆>` 运行 `dsh --profile web --dump-config`：
   退出码 0 且解析 warn（applyEntryPatches 未命中在此显形）为空 → 通过；
4. 通过才 rename 到真实 home（热应用随之自动发生）；失败不 rename、丢弃克隆、
   真实文件不落盘，UI 给可读错误。

采用克隆而非 `--patch <tmp-overlay>` 的理由：overlay 是**叠加层**，与"替换真实补丁文件
的某段"语义不等价（会把当前行再叠一遍、产生重复/非预期合并），校验对象与落盘对象
不一致。克隆同时把 R20（dump 的 prepareProfile 写副作用）隔离在克隆内，顺带规避与
运行中实例的 home 写竞争。

### 5.2 激活门（新装/启用后）

结构门拦不住模块 import 失败、apply 抛错、缺 client bundle。对「新插件安装 / 停用→启用」
默认追加一次 **重启 + 健康检查**：3080 可达 + 启动日志无 loader FAILED /
`N entries did not activate` / pending waiting for 字样 + 该条目在有效组合中激活。
失败 → rename 回 `.bak`（本身一次热应用）→ 再重启 → 报告并留日志。

### 5.3 热启用与兜底（用户决策 2026-09-05）

热应用（保存即热应用）作为默认加速路径；一旦热应用失败、或无法当场判定是否生效
（静默盲区 R9/R5/R11），**兜底动作 = 提示"未生效"并提供一键重启**——冷重启是权威
激活验证，用户无需手工排查。即"热不行就重启"。

### 5.4 冷启动失败恢复（R19）

冷启动解析失败是硬失败（退出码 1 + stderr 审计文本）。助手捕获后给可读错误页 +
「用 `.bak` 一键回滚并重启」。

## 6. 操作原语 `plugin_store.py`

模块约定：纯 Python 标准库；所有函数幂等、可跑在后台线程；每步落日志（复用
`log_line` / `_append`）；**全部路径显式传 home**（默认 `os.environ["DSH_HOME"]`，
无则报错——本机已确认该变量生效）；删除 `web_clock_overlay` 对
`Path.home()/.dsh` 的硬编码。

| 函数 | 语义 |
|---|---|
| `discover_sources(home, project) -> list[PluginSource]` | 扫描项目 `plugins/`、`assets/plugins/`、`assets/plugins.tar.gz`；判据 §3 |
| `status(plugin, patch_file, ledger, dump) -> State` | §2 三态合成 |
| `validate_package(dir) -> list[str]` | 安装前置校验：name 恰为 `@dsh-user/<目录名>`、lib/index.js、dsh.client→lib/client.js |
| `install(home, plugin)` | ① 同步目录 → 共享锚（幂等整目录覆盖）；② 台账加行 → 自有段重写 → 结构门 → rename |
| `set_enabled(home, plugin, enabled)` | 改台账 disabled → 段重写 → 结构门 → rename |
| `uninstall(home, plugin, keep_files=False)` | 台账删行 → 段重写 → 等热应用落定 → 停 web → 引用扫描零引用才删共享目录；任何疑似引用（含文件名命中、未知 overlay）即保留并明示 |
| `sync(home, plugin)` | 仅重同步共享锚目录（不碰补丁） |
| `reference_scan(home, slug) -> list[str]` | 扫全部 profile 与 home 层补丁 `name:` 引用（受限方言解析，非纯文本，避免被注释/多行骗过） |
| `apply_and_restart(gui, ...)` | 写回补丁 → 若内嵌 web 在运行则停（等 `_pump_web` 线程退出）→ 重启（复用 `_launch_web` 改造版） |
| `ledger_load / ledger_save(home)` | 台账读写，损坏即 fail-loud |
| `parse_patch(path)`（私有） | §3 受限方言解析器，遇拒改形态抛错不落盘 |

`dsh --dump-config` 调用封装为 `run_dump(home, patch_bytes) -> DumpResult`（退出码、
warn 行、条目表），结构门与状态合成共用；激活门健康检查封装
`health_check(url, logs) -> bool`（§5.2 信号）。

  现 worker 直呼 messagebox 为反例，新增代码禁止）；stop→restart 需等旧 `_pump_web`

- 错误/未生效提示（R12/R13/R15/R19）：结构门失败、热应用失败、判定不了、client 需刷新、
  冷启动失败 → 各给用户可读提示与动作（重试/一键重启/刷新页面），并落日志区。
- 导入：选目录或 zip → 校验 §3 判据 → 拷入项目 `plugins/<目录名>` → 重新扫描即现。

## 8. 来源、打包与预设

- 离线分发：`assets/plugins/<名>/` 与 `assets/plugins.tar.gz`。
  **source.tar.gz 不可作插件分发源**：`plugins/*/lib` 为 git 忽略产物、插件整体未跟踪，
  源码快照不可靠（保留 v0.3 §10 结论）。
- 打包自检脚本（独立，非 installer.py）：从选定插件收集
  `package.json + README + lib/* + install/patch.example.yml` 生成 tar/目录；
  校验项同 §3（name 前缀、lib 存在、dsh.client→lib/client.js）。
- v0.1 只留导入接口；在线下载中心与 catalog 预设（PluginRegistry：名称→来源 URL/版本）
  归 v1/v0.3，白名单之外不下载（R17 信任边界）。

## 9. 与现状的衔接（time-context 老逻辑）

`web_clock_overlay`（installer.py 149）现于 `_launch_web`（602）里无条件
`--patch plugins/time-context/cordis.patch.yml`。改造后：
- 补丁文件里**已有 time-context 行**（任何来源）→ `web_clock_overlay` 返回 None（不双挂）；
- 没有且文件存在 → 保持现状（向后兼容）。
toast / lsp-echo / conversation-summary / workspace-files 等不再依赖各自 install.ps1

## 10. 风险与盲区（含 2026-09-05 新增）
